# 出力フォルダー機能 実装手順

承認済み設計: [OUTPUT-FOLDER-PLAN.ja.md](OUTPUT-FOLDER-PLAN.ja.md)。既存形式を維持し、以下の順に実装する。

- [x] Coreの回帰試験を追加し、未実装で失敗することを確認する。対象: 外部出力・原本不変・親フォルダー保護・再起動・移行失敗・再登録。
- [x] `outputs.rs`に所有情報・保存先検証・コピー移行・再登録・旧出力整理をまとめる。registryに出力先・所有トークン・旧出力一覧・設定を追加する。
- [x] `store.rs`の保存先解決、`projects.rs`の排他・削除、`generations.rs`のwriterロック、`backup.rs`の複製をプロジェクト別出力へ対応する。
- [x] Coreテストを通し、別の設定領域から同じ出力を開いた場合にも出力側の共通ロックが効くことを試験する。
- [x] Service／CLI／ローカル管理APIへ作成・移行・既存出力を開く・入力再指定・旧出力整理を追加する。
- [x] Reactへ入力・出力選択、保存先のプレビュー、プロジェクト設定、移行操作、旧出力整理を追加する。AppDataの常時表示を除去する。
- [x] Desktopは移行・入力変更時に監視を停止し、成功／失敗後に監視状態を復元する。
- [x] 外部出力を含むバックアップと新規保存先への復元を試験する。
- [x] Rust／React／Desktopの検査・実機確認を実施し、READMEとWindows配布物を更新する。CIの結果はGitHub Actionsを参照。

保存先は`選択した親/MarkdownKnowledgeHub/<project-id>`。所有マーカーは`project.json`。削除はパス・所有トークン・既知の生成ファイル構成を検証してから行い、親フォルダーと原本は対象にしない。プロジェクト単位のロックを出力の共通領域にも置き、異なる設定領域からの同時利用を保護する。
