# 入力・出力フォルダー選択機能の追加計画

状態：承認済み。実装・検証は[0.3.0記録](RELEASE-0.3.0.ja.md)を参照。

## 目的

お客様がプロジェクトごとに「読み込むMarkdownの場所」と「生成データを保存する場所」を画面から指定できるようにする。Windowsデスクトップを主対象とし、Web版はこのPCの127.0.0.1限定で共通機能を利用する。ネットワーク公開は行わない。

## 用語と保存内容

|画面の名称|意味|アプリの操作|
|---|---|---|
|入力フォルダー|お客様が用意したMarkdownのある場所|読み取りのみ|
|出力フォルダー|お客様が選択する生成データの保存場所|アプリ専用の子フォルダーを作成して保存|
|アプリ設定|最近開いたプロジェクト、出力先の参照情報など|既定のユーザー用設定領域で管理|

選択した出力先へ、SQLiteの文書・リンク情報、Tantivyの検索索引、閲覧用の本文コピー、プロジェクト情報を保存する。アプリ設定の保存場所と、本文を含む出力先を混同しない。通常画面にWindowsユーザー名を含む設定保存先は表示しない。

ここでいう出力は、アプリで再利用する生成データ。独立したHTMLサイトやリンク図PNGの書き出しとは別機能であり、今回の追加には含めない。

## 採用案と比較

1. **プロジェクトごとの出力先（採用案）**：案件ごとに入力と出力を分離でき、選択した案件だけを移行できる。
2. アプリ全体で1つの保存先：実装は小さいが、案件別の管理ができないため今回は採用しない。
3. 入力フォルダー内への自動保存：原本の領域へ書き込むことになるため採用しない。

## 新規作成の画面

```text
新規プロジェクト

プロジェクト名   [販売システム仕様書                ]
入力フォルダー   [D:\Specifications\Sales          ] [選択]
出力フォルダー   [D:\MarkdownHubOutputs             ] [選択]

生成データ保存先：D:\MarkdownHubOutputs\MarkdownKnowledgeHub\<project-id>
原本Markdownは変更しません。
出力には閲覧用の本文コピーが含まれます。

[作成して開く] [キャンセル]
```

新規作成時は出力先を必須とする。前回選択した出力親フォルダーを候補として表示するが、実際の保存先を作成前に明示する。フォルダー選択のキャンセルでは何も作成しない。

既存ファイルのある親フォルダーも選択できるが、アプリは専用の子フォルダーだけを管理する。プロジェクトIDによる分離で同名プロジェクトの衝突を避ける。既存の専用フォルダーがある場合は上書きしない。

## 既存プロジェクトと出力先変更

- 従来のAppDataや`--data-dir`配下にある索引はそのまま読み、既存登録を失わない。
- プロジェクト設定に「入力フォルダー」「出力フォルダー」「出力先を変更」を表示する。
- 変更時は保存先と必要容量を確認し、そのプロジェクトの監視・更新を止めて排他を取得する。
- 完成済みデータを新しい専用フォルダーへコピーし、件数・検索・所有情報を検証する。
- 成功後に登録の参照先を切り替え、監視していた場合は再開する。画面も新しい出力先から読み直す。
- 途中失敗やアプリ終了で旧出力を失わない。旧データは自動削除しない。移行成功後に「旧出力を削除」で専用領域だけを確認付きで整理できるようにする。

「既存プロジェクトを開く」では出力側のプロジェクト情報を読み込み、再登録できるようにする。入力が見つからない場合は保存済み索引の閲覧を維持し、更新時に入力フォルダーの再指定を案内する。不明な形式やID衝突を黙って上書きしない。

## 原本と既存ファイルの保護

- 入力と出力が同じ場所、入力配下への出力、出力専用領域の内側に入力がある構成を拒否する。
- 他プロジェクトの入力フォルダーとの重なりも検査し、別の原本領域に生成データを書き込まない。
- Windowsの大小文字・相対パス・ジャンクション等を考慮し、実際の保存先で判定する。
- 書き込み権限、空き容量、既存専用フォルダーの衝突を作成・移行前に検査する。検査後の権限変更や容量不足による実処理の失敗も扱う。
- 所有マーカーとプロジェクトIDでアプリの管理領域を識別する。削除は検証できた専用領域に限定し、選択した親フォルダー全体や原本を削除しない。

## 実装順

|段階|変更内容|主な対象|
|---|---|---|
|1|プロジェクト別の出力先を登録し、旧形式を維持|Coreの登録・保存先解決・ロック・世代管理|
|2|入力／出力の選択画面、保存先の説明、表示文言の整理|React、Service、ローカルAPI、Tauri|
|3|監視停止を含むコピー移行、失敗時の復旧、既存出力を開く|Core、Desktop、プロジェクト情報|
|4|削除・再作成・バックアップ／復元を新しい保存構成へ対応|Core、CLI、管理操作|
|5|テスト、Windows実機確認、文書・配布物更新|Rust/Reactテスト、CI、README、exe/NSIS|

Coreは現在、全プロジェクトをアプリのデータ領域に保存している。画面に出力欄を足すだけでは足りないため、プロジェクト別の保存先解決を先に導入し、検索・監視・削除など全操作を同じ保存先へ統一する。

## 完了条件

1. 画面から入力と出力を選び、指定した専用領域に生成データができる。
2. 入力MDの作成・更新・削除をアプリが行わず、前後の内容ハッシュが一致する。
3. アプリ再起動後も同じ出力からプロジェクト・検索・Wiki・リンク図を利用できる。
4. 従来形式から移行でき、途中失敗・終了でも旧データで再開できる。
5. 出力の移行中に監視や削除が競合せず、成功・失敗の両方で状態が明確になる。
6. 他のファイルのある親フォルダーを選んでも、作成・再作成・削除で既存ファイルを変更しない。
7. 入出力の重なり、書込不可、容量不足、キャンセル、不正な所有情報を安全に扱う。
8. Windows/LinuxのCore CI、React CI、Windows Desktopビルドを通し、配布exeで操作確認する。

## 今回の範囲外

HTML／PDF／画像としてのエクスポート、ネットワーク公開、外部自動更新配信、コード署名証明書の取得。これらをフォルダー選択の実装に混在させない。
