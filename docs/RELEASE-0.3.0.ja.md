# 0.3.0 入力・出力フォルダー機能の検証

## 変更内容

- 新規プロジェクトで入力と出力を選択し、実際の専用保存先を作成前に表示。
- 出力は`選択した親/MarkdownKnowledgeHub/<project-id>`。本文コピー、SQLite、検索世代、所有情報を保持。
- 従来の設定配下の索引を維持し、プロジェクト設定からコピー移行できる。
- 移行先を検証してから切替。旧出力を保管し、確認付きで専用領域だけ整理。
- 保存済み出力の再登録、入力不在時のキャッシュ閲覧、入力の再指定。
- 移行・入力変更時にDesktop監視を停止してから実行し、元の監視状態を復元。
- 外部出力のバックアップは本文・検索世代を内包し、稼働中の出力先への参照を引き継がない。
- アプリ設定の絶対パスを画面下部に常時表示しない。

## 自動検証（Windowsローカル）

Rust workspace 42件（Core unit 26、Core integration 8、Service 2、API 6）、React 11件、Desktop起動設定1件、合計54件を実行し成功。workspaceの全ターゲットClippyを警告エラー扱いで通過。Rust／Desktopの書式、TypeScript、Web本番ビルド、workspace release、Windows Desktop release、NSIS生成を確認。

追加回帰試験は外部出力・再起動、原本不変、親の既存ファイル保護、移行失敗時の旧出力維持、所有情報不正、ID衝突、入出力の重なり、空き容量不足、別設定領域の共通ロック、入力不在、入力変更時の同一サイズ／mtime、外部出力のバックアップ／復元、管理API拒否系を含む。不明なファイルが検索世代内に追加された場合も、自動回収・削除を中断して保持する。

## Desktop実機確認

独立したテスト設定と合成Markdown 2件で、新規作成→指定した外部出力でWiki・リンク表示→監視開始→Windows標準フォルダー選択→出力先変更→監視再開→アプリ終了・再起動後の再利用を確認した。

入力2件と、両方の出力親フォルダーの既存ファイル2件について、作成・監視・移行後のSHA-256が開始前と一致。旧出力も残り、設定と本文は新しい出力を参照する。実顧客文書はこの試験では変更していない。

## 配布・CI

バージョン0.3.0の単体exeとNSISインストーラーを生成。CLI exe、SHA-256一覧とともにローカルのoutputsへ配置する。実行中の旧版を終了してから差し替える。

非公開リポジトリの[GitHub Actions](https://github.com/yuanyeee/markdown-knowledge-hub/actions)でWindows／Linux Rust、React、Windows Desktopを検証する。実行結果は該当コミットのActionsを参照。

コード署名は証明書未準備のため未署名。ネットワーク公開、外部更新配信、HTML／PDF／画像の独立エクスポートは今回の対象外。出力には原文コピーが含まれるため、選択した保存先にも原本と同等のアクセス権を設定する。
