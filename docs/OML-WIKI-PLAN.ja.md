# OML Wiki 実装計画

既存のTauri・React画面とRust索引を使い、OML専用Wikiをローカルで閲覧する。参考は nashsu/llm_wiki のツリー、本文、根拠表示と関係図。

1. 初版は OML Utilities の生成済みMarkdownを入力とする。文書の見出しと「使っているモジュール」表を抽出し、モジュールページと依存リンクを生成する。出典は元仕様書の相対パスと行番号。参照が一意に解決できない場合は未解決欄に記録する。
2. Rust Coreに変換処理、CLIに生成と登録の入口を設ける。新規の専用フォルダーにWikiを出力し、既存のTantivy、Backlinks、関係図を使う。原本を読み取り専用で扱う。LLM APIは不要。
3. 合成仕様書で依存方向、同名、未解決、原本保護を検証する。利用可能な実仕様書で抽出件数を確認する。
4. 次段階では OML Utilities のXMLまたは構造化出力を検証する。モジュールと要素IDで照合し、画面遷移、アクション呼び出し、ER、影響範囲に拡張する。参照が取れた種類から順次追加する。
5. デスクトップで生成操作、種類別のツリーと色分け、選択ノード周辺の強調、出典プレビューを追加する。既存プロジェクト探索画面から生成済みWikiを開ける形にする。大規模案件ではモジュール集約を初期表示にする。

初版の受入条件は、2モジュール以上を生成して、Wikiから参照先へ移動でき、参照元と関係図に同じ関係が出ること。構造化解析の受入では実モジュールを照合し、解決数・未解決数と根拠を記録する。ネットワーク公開は対象外。

## 初版の操作

OML Utilitiesから出力済みのMarkdownフォルダーを用意する。以下の生成先は未作成のフォルダーを指定する。

```powershell
cargo run -p hub-app -- compile-oml-wiki D:\OML\docs\md D:\WikiWork\OML-Wiki
```

デスクトップの「新規プロジェクト」で、生成した D:\WikiWork\OML-Wiki を入力として登録する。検索で「OML Wiki」を開くとモジュール一覧があり、各ページに依存先・出典・元仕様書がある。参照元はBacklinks、関係はリンク図で確認する。生成コマンドは元仕様書フォルダーと重なる出力を拒否する。

初版は仕様書ファイルごとにページを生成する。複数ファイルに同じモジュール名がある場合は、該当する参照を未解決として扱う。モジュール参照表の対応は、通常仕様書の「参照モジュール」と拡張機能仕様書の「使っているモジュール」。後者は利用元から拡張機能への関係に変換する。

## 検証結果

実仕様書334件のうち、対応する見出しを持つ327件から仕様書ページを生成した。抽出した依存表の547行はすべて一意に照合できた。これは対象の表に記載された参照の結果であり、OML内の依存関係の網羅率は未計測。モジュール一覧を含む328ページを索引化し、検索を確認した。合成テストでは正方向・逆方向の表、未解決、Backlinks、関係図の辺、原本保護を検証した。
