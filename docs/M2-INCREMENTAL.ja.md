# M2 前半: イベント差分更新と文書別リンク

## 方針

M1で未達だった10万件の差分1秒目標に向けて、ファイルイベントで指定された相対パスだけを照合する。本文変更だけなら出リンクの再解決も変更文書に限定する。追加・削除時は同名候補が変わるため全リンクを再評価し、解決結果が変わった行だけを書き換える。全体scanと60秒間隔の照合は維持する。

## 実装・検証手順

- [x] `scan_paths(project, paths)` の統合テストを先に追加。無関係な不正UTF-8文書があっても指定文書を更新できること、追加・削除による同名候補の変化、ルート外・シンボリックリンク拒否を検証。
- [x] scanの候補選択を全体／指定パスで共有し、指定パスはハッシュ照合を必ず行う。失敗時は既存索引を維持する。
- [x] notifyのファイル変更を250msでまとめる。曖昧なイベント、フォルダ操作、再走査要求、エラーは全体scanに戻す。イベントが連続しても60秒ごとに全体照合する。
- [x] `links_page(project, source, offset, limit)` と文書専用APIを追加。最大200件のページを安定順で返す。先頭5,000リンクの外にある文書もテストする。
- [x] Reactは文書を開くときに該当文書のリンクページを取得し、続きの取得を提供。本文のリンク移動は取得済みページに対応する。
- [x] ベンチマークに指定パス差分時間を追加し、10万件で全体scan経路と比較する。合成データの制約は引き続き明記する。
- [x] Rust／Webテスト、ビルド、実ブラウザ、Windows監視を確認。GitHub CIとmainへの反映結果はGitHubの履歴／Actionsを参照。
